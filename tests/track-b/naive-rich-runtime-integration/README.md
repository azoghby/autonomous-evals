# Rich expert text runtime staged integration

Run from the repository root:

```sh
node tests/track-b/naive-rich-runtime-integration/run.mjs
```

The runner archives source commit `06d8a15` (override with `RICH_RUNTIME_BASE` only for a source-compatible reviewed commit), then applies `expert-workflow-integration`, `naive-rich-contract-integration`, `naive-text-runtime-integration`, and `naive-workflow-schema-integration` in order. Every touched preimage, artifact postimage and applied postimage is SHA-256 checked. `RESULTS.json` identifies the full source commit and exact manifest/patch bytes tested. `SUPPORT-PINS.json` pins all transitive core, server and Workflow source modules in that staged tree. Actual owner source files are never edited by the runner. SQL migrations run only inside disposable PGlite databases.

`owner.test.ts` invokes the actual `createExpertTextRuntime` factory, real SQL task and operation stores, original 0025 and candidate 0026 SQL constraints/triggers, artifact admission/publication, checkpoint stores, SessionService and budget ledger. It seeds retained independently reviewed expert data, authenticated receipt/request operations and an exact immutable freeze. Provider transport is the existing fake Naive sessions port behind the real SessionService. Customer target HTTP is a JSON transport fake; rubric transport throws locally to exercise unavailable judgments. No external network, email, paid request or production database is used. Its ServiceContext cost sink is an explicitly substituted idempotent SQL fixture, so these tests prove runtime receipt replay rather than the separately tested application's global cost sink.

`projection.test.ts` runs the actual text executor and lossless contract projection with target/judge ports replaced locally. It distinguishes objective failure, subjective concern, inconclusive and infrastructure results. `workflow.test.ts` executes actual job Workflow control flow while mocking external steps/hooks/timers; `step.test.ts` exercises actual expert evaluation/report step policy with its runtime and report transport substituted. These controller tests prove pending/no-assessment holds never deliver or settle and assessment limitations survive report publication. They do not establish hosted durable timer behavior. Original concrete adapter SQL integration, Workflow evaluation and regression consumer tests are run unchanged as compatibility coverage.

The runner executes Next type generation, strict full core/web TypeScript, focused integration/legacy tests, the original `npm test` suite with two workers, and a production webpack build. `RICH_RUNTIME_SKIP_BUILD=1` is an explicit faster iteration mode whose results record `build: null`; a final acceptance run must omit it. Retained dependencies come from `/tmp/sandbox-generation-deps.cBCEai/node_modules`, `/tmp/workflow-bootstrap.JpxCTM/node_modules`, and `/tmp/expert-validation-extra-deps/node_modules`. The extra cache supplies exact `@ai-sdk/react` 4.0.169 but `@vercel/analytics` 1.6.1 substitutes for declared ^2.0.1. Thus a successful local build is supplementary compilation evidence, not an exact clean-lockfile install acceptance. No source substitutions or type skips are used.

This is an unapplied adoption candidate. Database migration registration, approved adoption, deployment and real provider/endpoint acceptance remain separate gates.

`FIRST-FULL-RESULTS.json` preserves the initial full candidate failure: 38 focused tests passed, type generation/core/web types/build passed, and original npm tests had 3546 passed/8 failed/2 skipped. Six mapping and two run-service assertions described the previous refusal behavior; review also identified malformed objective-concern and inconsistent target-state handling that required correction. This receipt is historical failure evidence, not final acceptance. The original suite intentionally skips tau2 retail scenario regeneration and the live Neon sandbox isolation/diff/cleanup test; final original-suite results must retain and name those limitations.

The initial broad run also could not load the Trace Audit suite because its committed `tests/track-b/trace-acceptance.json` fixture was omitted from the archive. Assertion totals alone therefore did not establish a clean full suite. The runner now obtains that fixture from the exact source commit with a pinned SHA-256. `PRE-FIXTURE-RESULTS.json` preserves the final source/types/build/focused evidence before this fixture correction. `rerun-full.mjs` verifies those unchanged source hashes, stages only the committed fixture, and reruns npm tests; `RESULTS.json.validationSteps` separates the original compiler/build harness revision from this supplemental full-suite revision.

For cloud-backed Git stalls, the runner optionally accepts `RICH_RUNTIME_ARCHIVE_CACHE` and `RICH_RUNTIME_ARCHIVE_SHA256`, with `RICH_RUNTIME_ARCHIVE_RECEIPT` defaulting to `FIRST-FULL-RESULTS.json`. It requires the exact completed archive path recorded by that receipt, the same source commit, and matching archive bytes. It extracts a fresh tree and checks every patch preimage/postimage. A mutable previous source tree is never reused. `SUPERSEDED-RUN.json` records the explicitly cancelled live archive that this verified cache replaced; it is not a failure receipt.
