# Canonical payment bridge

`source/apps/web/src/server/current-payment.ts` is an additive, readable applied source. It is built against f88811c's staged current app, whose actual application parent is 0398517. It does not edit or replace either historical artifact.

The bridge reads current `jobs`, latest `quotes`, and the five latest customer messages directly. It requires a genuine Workflow run, an owner matching tenant/customer, current authorization-to-test, and fresh owner policy authorization. The CompanyRequest projects bounded existing `sanitizeIntake` fields; it never reads `job_credentials`. Changed canonical input invalidates replay instead of overwriting a saved release binding. Clarification resumption requires an explicit reviewed new-round handoff; this bridge starts round zero only.

A company fixed quote must exactly match the current quote's package, version, code-owned price, scope, deliverables, and environment. Independent qualification that produces different scope is an explicit `quote_contract_mismatch`; no paid job is silently repackaged. Compatible quotes return the actual owner `POST /api/jobs/:jobId/accept-quote` action. That existing route handles explicit customer acceptance, Checkout creation/reuse and the original quote_accepted Workflow signal. Enqueuing this action does not accept the quote or authorize payment. The startup owner must expose it to the authenticated customer through the retained communication outbox.

Stripe ingestion first verifies the raw signature through the injected current SDK verifier. It requires the existing durable canonical payment row, binds the event, session, PaymentIntent, environment, exact currency/amount, job/version and immutable quote digest, then atomically queues native SQL outbox work. The original webhook's `recordPaymentFromSession` remains the canonical row writer. Scoped ingestion ignores legacy unbound jobs while strict ingestion reports an explicit missing binding. SDK verifier configuration is a trusted owner capability; no credentials or customer authentication are serialized into Workflow.

The SQL ledger retains same-event duplicate/conflict checks across process restarts. Post-bootstrap and scheduled drains publish only canonical usable receipts. Verification compares the passed receipt with its durable row and rechecks the native SQL event/binding plus the canonical authorization. Any partial refund or cancellation revokes the entire quote's autonomous payment authority conservatively. It never issues a refund, releases a hold, or resumes cancelled work. Provider event authenticity is not inferred from ordinary payment rows alone.

Per-finding manual authorization, variable capture, and zero-finding release remain the existing business contract. The fixed CompanyRequest payment port cannot represent that contract and fails explicitly; an authorization cap is never a prepaid fixed quote. Current x402 settles USDC on Base Sepolia, while release receipts require USD. `ingestX402` therefore fails with `usdc_release_currency_contract_unsupported`; there is no fabricated USD conversion or provider receipt. Existing x402 charging/resumption remains unchanged.

Remaining activation gates: approved server-only owner composition, least-privilege migration role, genuine configured Stripe webhook delivery including refund/cancel events, accepted compatible current quote, durable genuine provider receipts, source-policy and evaluation adapters, and actual provider/configuration verification. No real provider event, network payment, secret, deployment or spend is performed by these artifacts or offline tests.
