# Pack composition

`applyPack(stage)` accepts a clean `stageComplete().stage`. It applies historical
projection and nonoverlapping execution hunks, then installs four reviewed merged
sources. Historical patches are unchanged. The parent stager owns pins, integrity,
canonical migration names, ordering and build validation.

`resolvePackBaseSuite()` performs fresh canonical authorization and reads the
immutable approved-data plan and readiness receipt. A planned but unready suite
blocks review. An admitted suite is resolved through approved admission and Text
`getSuite`, without manufacturing `suite` or `design` checkpoints. The nondata
path discovers only the retained completed design identity, then reauthorizes via
Text `getSuite`; orphan data tasks refuse design fallback. Neither path redesigns
or dispatches targets. POST binds the explicitly reviewed base digest.

The driver retains approved-data pending/reconciliation behavior, all Calendar
returns and stable core operation identity, private data provenance, and base12
remediation. With packs enabled it validates immutable approval, tenant,
environment, Workflow, revocation, source rules, reviewed receipt, exact supported
base suite and actual target digest **before baseline dispatch**. Execution checks
those bindings again through its secured runner. Appended evidence is attached to
the existing remediation envelope, and complete limitations reach both artifact
and report. Coverage gaps retain the draft report/evidence and block completion;
known failures and coverage gaps remain simultaneously visible.

No supported pack is globally quarantined here. The unchanged trusted registry
and secured runner decide each case using pinned source semantics. Calendar packs
remain explicitly blocked. Patched-target pack remediation, full-artifact
comparison and monitoring lifecycle extension points remain separate from base12
remediation; this composition grants none of those authorities.
