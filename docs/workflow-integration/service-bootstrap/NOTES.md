# Service/bootstrap patch layer

This artifact applies to Track A `f0068733ca49c37f40fd7de279325f21a4b5fbbb` with the core source overlay pinned to `5906961c2a70c0d6d2999cf7086689402ff60f5b`, in the root SERIES order. No application, engine, manifest, contract or deployed database was edited in the working checkout.

`0001-rich-service-bindings.patch` supplies actual server composition for the rich Text and Calendar factories. The producer layer calls this API instead of the unavailable legacy boolean closures. It rechecks the canonical stored Workflow run, environment, package, customer, credentials, stable target revision and branch ownership at every factory resolution. It uses the app's existing intake rehydration/credential decryption API and the engine's secure HTTPS target clients; credentials remain inside server closures. Targets change identity when endpoint/model/prompt/reference, admitted revision or encrypted credential record changes. A bounded branch pool is shared during an invocation and disposed by the producer's `finally`.

The real service selector no longer silently substitutes the lite engine. Shared Naive construction now requires explicit pinned role versions, a stable budget period and stable idempotency namespace, and calls the parent's read-only `ensureAgents(..., {directory, dryRun:true})` attestation before using them. It never provisions an agent from a request. This inspection is production runtime code; it was not called against a provider during this task.

The authenticated operator admission endpoint is `POST /api/operator/jobs/:jobId/workflow-binding`. It uses the existing `requireOperator`, credential decryption and job APIs. A customer cannot approve their own cases. Text admission supplies a nonsecret `targetRevision`; Calendar admission additionally supplies exactly twelve schema-valid cases, with the signed-in operator's reviewer ID and approval. Conflicting admission replay is refused; internal fixtures require separate trusted fixture seeding. No endpoint accepts a branch connection, target credential or arbitrary checkpoint identity. The existing generated investigator review still applies to text suite admission. Calendar's reviewed cases are externally supplied by an operator; this patch does not invent a calendar scenario designer agent.

The separate transactional migration `apps/web/migrations/001-workflow-integration.sql` creates canonical bindings and cost keys. Deployment must apply it with the listed core/progress/data migrations before workers start; no request executes DDL. The cost sink commits its global idempotency key and app ledger row in one pinned transaction, refuses changed job/session/amount metadata under the same key, and supports acknowledged-write replay. Migration backfills historical keyed rows; duplicate historical keys abort for reconciliation. Historical unkeyed costs require separate operator reconciliation before replay is allowed. The same sink is used by `ctx.recordCost` and the decorated durable agent runner. This does not imply external execution and local accounting are one atomic transaction.
