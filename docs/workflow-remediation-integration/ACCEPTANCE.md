# Boundaries of the appendable remediation delivery

This delivery authorizes no deployment or external dispatch. Apply and review the
append after the pinned Workflow series and integrate the new accounting sources.
The archive staging harness is a test composition, not an application merge.

The application owner must apply the optional migration through its normal process,
check actual PostgreSQL isolation/transactions and permissions, and admit the
canonical target with request-message-only stateless semantics. Server-owned
identity must select the saved suite, baseline run and confirmed finding. Customer
strings must never construct endpoint configuration, SQL/checkpoint keys, a trial
receipt, a tool invocation, or an arbitrary code patch.

Reservations and evidence do not create remote attestation. The secured adapter
records the actual immutable serialized request handed to the trusted transport.
A remote endpoint can ignore it, maintain hidden state or serve another model.
Only full replacement prompt patches are supported. Historical Trace evidence,
unsupported patch kinds, absent original failures, missing rubric/reference,
regressions and ambiguous dispatch remain unverified or blocked.

A complete successful offline fixture must retain the baseline suite/run/finding,
all twelve unchanged frozen scenarios/checks, the proposed patch digest, the fresh
trial executions, twelve payload-linked application receipts, known/unknown usage,
reservation/settlement state and complete detailed verification. Passing base12
makes no claim about the separately gated appended pack. Never synthesize passing
appended cases or silently exclude quarantined scope.

Unknown provider usage or price is unknown monetary cost. It is not a zero-valued
Naive session entry. Durable holds and reconciliation must survive process loss,
late observations and lost acknowledgement. An outbox delivery may repeat; the
shared global Workflow keyed cost sink must reject conflicting replay and commit
the canonical cost and key atomically. Never delete an ambiguous hold or create a
new operation identity to redispatch an unknown external effect.

Before live acceptance the owner must validate actual authenticated Workflow and
operator access, credential rotation, tenant-isolated private evidence/report
reads, inventory/report propagation, database restart and competing-worker races,
actual provider usage/pricing and live known-buggy/fixed target behavior. Offline
injected transports and PGlite prove none of those hosted outcomes. Existing
Workflow series acceptance obligations continue to apply.
