# Generic Naïve text source adoption candidate

This is a combined, unapplied source candidate. It registers the real canonical text builder lazily in the existing application factory and retains the existing expert text branch. It adds no competing job Workflow, migrations, production configuration or deployment.

`EVAL_SERVICES=real` plus `EVAL_NAIVE_METHODS=designSuite,runSuite,investigate` selects the supported generic text sequence. Each selected method requires positive safe-integer reserved budget before owner/provider construction and never falls back to lite. Exact comma-separated method names and `EVAL_REAL_BRANCHES=0|1` are validated; omitted branch configuration preserves legacy behavior. The real branch flag controls simulator services independently. Selected generic text bypasses simulator branch creation, preserves the admitted public suite identity and prevents post-admission red-team mutation. Workflow evaluation and version comparison remain explicitly unsupported. Remediation and rerun owner runtimes remain unsupported; selected generic jobs do not silently run legacy lite fixes, and their reports explicitly say no fix/rerun verification occurred.

Canonical SQL authority binds owner, environment, intake, target credentials, design/run identities and current engine admission. Independent admission replays exact retained engineer/reviewer dispatches, schemas, pinned versions and completed outputs through deterministic design gates. Rich objective, rubric and inconclusive results remain intact. The existing shared budget ledger bounds session/Jude reservations while durable generic allocations and task budgets prevent retry specifications from drifting. Measured keyed cost receipts survive lost acknowledgements and are separated from dispatch/publication permission.

Selected admission waits use a durable 30-minute timer for at most seven days; existing provider operations use a separate 30-second timer for at most one day. Both retain one event read, support cancellation, and reconstruct the same durable task/checkpoint identities. Exhausted waits return `on_hold`; they do not invent a new provider operation. Unselected legacy errors and fallbacks retain their behavior.

Generic report publication reads exact retained run/investigation evidence and rechecks owner, credential, target and approval authority without constructing providers or requiring a paid budget. Entirely unassessed baselines hold delivery and settlement. Assessed reports include coverage and limitations. Private artifacts upload before a pinned transaction atomically commits exact findings, report paths, delivery deadlines and an immutable publication receipt under current authority. The Workflow skips its legacy delivery mutation once that receipt exists. Receipt recovery runs before a delivered text job is treated as finished, including after routing flags are removed; expert/legacy jobs have no generic receipt and retain their existing path.

Post-delivery recovery uses existing idempotent settlement and a durable notification-attempt claim. An ambiguous notification claim never automatically resets or redispatches. A completed claim records completion of the existing notification step, whose current implementation can log a failed email and return; it does not prove successful email delivery. Unknown publication/receipt outcomes return `on_hold` and do not overwrite a committed delivered state. External storage cannot join the SQL transaction, so rejected publication may leave private orphan uploads. No exactly-once email claim is made.

The proposed source/test postimages are under `postimages/`. Tests occupy normal application `*.test.ts` paths and have no artifact/staging imports, so standard `npm test` covers them after adoption. `manifest.json` records exact preimages/postimages and `owner.patch` is reviewable before source approval. Prior slice artifacts remain frozen and unapplied. Validation receipts will identify the exact integration baseline and local dependency graph; no hosted/provider acceptance is implied.
