# Authenticated expert evidence review surface (owner review artifact)

Eight proposed application postimages in `source/` add `/operator/expert-reviews`, its operator-console link, a bounded queue/detail/submit API and a structured evidence review form. Actual application source remains unchanged. The patch is pinned at `9eb9e4c82a69be2ae9e997efdb747e8b6d658acd`; preimages were also checked compatible with `11d7ff2`. `manifest.json` records exact per-file pre/post hashes and the patch hash. Regenerate packaging with `python3 docs/expert-review-surface-integration/build-artifact.py`. No migration is added.

`GET /api/operator/expert-reviews` inventories currently authorized pending contribution/corpus snapshots, accepting only an optional bounded opaque keyset cursor. `GET /api/operator/expert-reviews/[jobId]/[kind]/[digest]` returns the exact retained snapshot, its checksum and the authenticated reviewer ID. `POST` requires JSON, an explicit attestation and that exact checksum; the server streams at most 450,000 bytes before parsing strict bounded input. Session identity never comes from the body. Contribution submissions contain exact answer/rationale/source judgments and qualification/consent/conflict attestations. Corpus submissions contain a deliberate decision and reviewed records. Stable corpus receipt IDs are server-derived from principal/job/snapshot/decision/body.

The existing server review helpers now reauthenticate the same current operator across awaits, bind the snapshot to canonical plan/task/input digest, recheck enabled plan/job/tenant/deadline and current secrets, and guard SQL mutation/replay. Contribution writes roll back on authorization revocation during the awaited write. Corpus receipts continue through the existing immutable authenticated review ledger; partial writes cannot publish an authenticated corpus decision. All API outcomes, including denials, are private/no-store and vary by Cookie. JSON content type and same-origin checks protect submissions; no endpoint invokes a provider, creates a grant, sends an invitation or spends money.

Source/case payloads, provenance, source identities, license restrictions, allowed uses and existing expert attestations remain immutable through this surface. Only source review fields and case verification judgments are editable. Authenticated reviewer identity is injected server-side, then exact answer context digests are recomputed against the final reviewed sources. A human review does not automatically establish data sufficiency or freeze a suite; the existing deterministic quality/admission gates still decide. Unknown/denied/mixed source permissions cannot be upgraded by checking an approval box.

The interface follows the existing Precision Black operator typography, hairlines, controls and spacing after reading `DESIGN_STANDARDS.md`. It shows private source content/provenance/permissions, exact expected answers, synthetic labels, qualification evidence, consent receipt and the immutable snapshot identity. No approval or attestation is preselected. Reviewer independence and deliberate exact answer/source decisions are required. Missing evidence remains unapproved; the contribution helper only records valid approvals and does not fabricate a separate rejection receipt. Corpus rejection is supported. Stale/conflicting submissions and revoked access discard the private detail; no snapshot is stored in local storage.

Queue pagination is bounded to 100 scanned unresolved candidates per request. SQL excludes terminal contribution/corpus decisions and malformed operation identities; each remaining snapshot is individually authorized and screened. The next cursor advances past the last scanned identity even when every item on a page is omitted for safety, so unreadable entries cannot permanently hide later valid reviews. The UI offers the next page and a Refresh action that restarts from the beginning to retry earlier pending snapshots. Cursors confer no authority: each page repeats current operator/plan/tenant/snapshot checks. This is a current pending inventory, not a historical decision browser.

## Verification

`RESULTS.json` and `evidence/` retain the final receipts. Root package.json, app package.json/tsconfig/next.config and core tsconfig matched the pinned base. Installed packages came from the retained local dependency installation, not a fresh install.

- 28 tests across three files passed, zero skipped. Six real PostgreSQL/PGlite tests execute actual POST handlers with the adopted 0025 migration, data-operation migration, production transaction adapter, immutable triggers and core stores. They verify contribution replay, corpus receipt/context binding, and rollback after awaited real contribution INSERT, corpus receipt INSERT and final corpus authority UPDATE when the principal is revoked. The other handler tests use a Map-based SQL boundary with real deterministic validators/ledger; one additionally executes actual queue SQL in PGlite, including pagination past 100 unreadable entries. UI model/static-render tests are separate. Cases include unauthenticated/nonoperator access, cross-job/canonical-task mismatch, changed snapshot, switched/revoked principal before and during mutation, secret rotation, source/license/expert-grant forgery, body bounds and exact successful/replayed submissions. UI model/static-render checks cover no auto approval, exact evidence selection, self-review refusal and escaped untrusted content.
- Next type generation and full staged web TypeScript passed.
- Local Playwright rendered the actual component with the existing compiled theme/fonts and intercepted fixture API responses. Desktop 1440×1000 and mobile 390×844 screenshots were inspected. The browser exercised initial disabled approval, explicit contribution submission once, empty-first-page cursor navigation to a later valid snapshot, no mobile horizontal overflow and private-detail removal after 403. This was an isolated illustrative interface fixture, not a real operator session or hosted end-to-end test.
