## Authority and operation

Only an authenticated operator can POST `api/operator/jobs/:jobId/comparison-binding`. Its body is the strict `comparisonBindingSchema`: suiteId, explicit base12/augmented scope, complete scenarioIds, two immutable version/target/configuration/branch/endpoint-slot bindings, and reviewed target-call/job budget policy. It loads the original retained rich suite/run/investigation from private SQL; callers cannot supply replacement baseline prose or prompts. Publication is INSERT-only with exact digest replay. Use the original `suite:${jobId}:frozen12` suiteId for existing Workflow baselines.

Configuration digest is SHA-256 of core `canonicalJson({endpoint:{...endpoint,apiKey:undefined},credentialCiphertext})`, with canonical credentials loaded internally. Current version equals this digest. Text baseline version reproduces original rich-services SHA-256 over **JSON.stringify** of endpoint, original `workflow_integration.bindings.target_revision`, and credential ciphertext; it must match original completed run_identity. Historical config/credentials must remain available; deletion/rotation refuses rather than relabels. Endpoint slots select existing canonical intake credential/configuration closures. An authenticated operator may additionally publish an immutable `endpointOverride:{url,model}` for a reviewed current target version, using the selected credential slot; compute configurationDigest after that override. This enables a concrete model/endpoint version comparison for an existing rich job without changing its frozen suite or accepting customer-supplied target URLs at comparison time. The baseline must still reproduce the original configuration hash. The existing HttpsJsonTransport enforces connect-time public-address/redirect policy; credential-bearing override content is refused at admission.

Calendar preserves original `run.versionLabel` (including historical `default`), and binds immutable configuration separately through `baseline.targetId = target:${originalLegacyTargetVersionHash}` plus configurationDigest and branch. It does not rewrite retained labels. Current version is its configuration digest. Every executable branch must still belong to this job and be ready in the existing branch ledger. Deleted branches require separately reviewed fresh authorized state; this patch never recreates cloud branches. Calendar uses the same retained systemPrompt on both sides and initializes its private suite through the actual `freezeSuite` factory without changing its content. Internal per-version suite checkpoint references are distinct because existing Calendar checkpoint identity includes target/branch; the compared frozen suite content/hash stays identical. A factory-lifetime dispatch counter prevents reproduction budget-hold reuse.

Canonical application inventory comes from the legacy Suite blob when present, otherwise the original rich producer's durable structured-progress expected inventory. Approved pack manifests and retained appended-pack manifests are unioned into that inventory as well. Missing inventory refuses. Admission can retain augmented scope, and the private inventory endpoint returns it in full; execution rejects augmented scope, missing/extra/duplicate cases or any difference from the reviewed twelve-case suite. Explicit base12 cannot hide appended cases.

Customer POST `api/jobs/:jobId/comparison` accepts only a stable client operationId; ownership/session checks happen before production construction. It compares configured authorized versions using the same frozen suite. This is an additive comparison entrypoint for delivered rich text/workflow jobs. It does not make the legacy `version_comparison` Workflow/boolean contract compatible. GET returns full rich evidence or complete admitted inventory as private, no-store JSON; downstream HTML must escape response evidence.

Cron reuses A's `requireCronAuth`, derives `monitor:${subscriptionId}:${UTC-day}` and requires active tenant/job/environment subscription with a provider subscription identity, a delivered nonmock job and retained one-time payment. It compares against the original retained baseline, never yesterday's run. Application tick identity (including full retained-baseline digest through the binding) is committed before any engine dispatch; core additionally commits per-side nonexpiring claims. Authorization/configuration/payment/subscription checks recur on replay and immediately before target calls. Concurrent/lost dispatchers cannot automatically redispatch.

The actual `PostgresBudgetLedger` reserves each target call against the shared job and evaluation-engineer period scopes, plus a monitoring tick scope. `NAIVE_BUDGET_PERIOD_ID` is required. Job cap cannot exceed A package policy. Target-call amounts are reviewed **exposure holds**, not measured costs or proof of a remote provider spending ceiling. Existing agent runner policy handles investigator reservations. Unmeasured target holds are never automatically settled or released. Provider-reported session receipts are inserted with immutable keyed SQL delivery and read per exact side operation. Retained baseline/design costs and missing target/hosting/investigation usage stay explicitly unknown. Known zero is not free execution.

Notifications are retained generic drafts in full rich results. Cron reports sent=0. No sending or email-thread code is used.

Operator POST `api/operator/jobs/:jobId/comparison-reconcile` accepts a stable operationId and `retain_blocked` or `accept_retained_completion`. It locks actual local checkpoints, derives its own evidence digest and records the authenticated operator. Acceptance requires an already completed application tick. It does not accept a caller's claimed external success, erase evidence, release a claim, refund a hold, overwrite a baseline, or re-enable ambiguous dispatch. Ambiguous work remains blocked pending separate authoritative external reconciliation; availability is intentionally limited.
