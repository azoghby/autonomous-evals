# Bounded hosted trace-audit demo gate

Baseline: source `c5d7d1d`, after cumulative runtime adoption. This is a proposed release gate, **not a hosted acceptance receipt**. Source merge and passing offline checks do not authorize migration, deployment, configuration changes or provider spending. Record the actual deployment commit if it advances beyond this baseline.

The narrow claim is: an authenticated customer submits an authorized synthetic trace; real Naïve sessions qualify it, audit its evidence and write the report; the hosted Workflow publishes an owner-readable report with measured cost receipts. This does not certify all eval methods, the complete company roster, expert acquisition, sandbox parity or the full [Naïve plan](../NAIVE_PLAN.md). Those goals remain open under [hosted acceptance](hosted-acceptance.md).

## Before live activation

1. **Schema:** inventory the actual staging database's Drizzle journal, sidecars, constraints, grants and existing task/hold/cost rows. Review the exact remaining SQL/order/hashes against [schema-plan.md](schema-plan.md), rehearse on isolated native PostgreSQL and retain migration receipts before deploying. Disabled feature flags do not eliminate shared stage/budget/cancellation schema dependencies. `npm run deploy` runs Drizzle only. The runner now offers `--dry-run --reviewed-constraints` for offline validation of the two exact code-pinned constraint replacements. An authorized live invocation omits `--dry-run`; it does not infer installed state or order. Do not blindly replay non-idempotent SQL, and inspect any uncertain commit outcome before retry.
2. **Current roles/provider:** attest the deployed runtime's pins/configuration and required resources for `NAIVE_AGENT_COMMERCIAL`, `NAIVE_AGENT_QUALITY_INVESTIGATOR`, `NAIVE_AGENT_COMPANY_OPERATOR` (`<id>@<version>`), plus any pins required by the actual factory. Verify active model availability, structured outputs, no unintended tools/handoffs, task/period caps and `NAIVE_API_KEY` authority. Historical four-role diagnostics are insufficient current proof; full expanded-roster provisioning is not a prerequisite for this three-role claim. `npx tsx scripts/naive-provision.ts --dry-run` is offline planning; provider attestation is a separately authorized live operation.
3. **Routing/budget:** use isolated staging `DATABASE_URL`/`DATABASE_URL_UNPOOLED`, `EVAL_SERVICES=real`, an explicit `NAIVE_BUDGET_PERIOD_ID` and a reviewed positive aggregate spend ceiling covering all runs/retries, role/session limits and shared job holds. Keep `EVAL_NAIVE_METHODS` unset/empty: these selections support generic text only, not trace auditing. No real simulator branch or target endpoint is needed for a trace-only fixture. Capture effective configuration names/values without secrets.
4. **Hosted authority:** clean pinned deployment, correct `APP_URL`, working customer magic-link delivery/session secrets, owner/operator access, Stripe test Checkout/webhook configuration, artifact storage and Workflow execution. Use normal sign-in; never enable `AUTH_DEV_LINKS=1` in production. Keep cron/outbound company activity controlled and use only the approved synthetic fixture. Confirm the explicit migration/deployment/spend authorization before executing.

## Smallest honest hosted acceptance

| Action (existing surface) | Required retained evidence |
| --- | --- |
| Sign in at `/signin`; customer `POST /api/jobs` with `package: "trace_audit"`, a synthetic trace containing a tool failure followed by a false success, `systemPrompt` and `authorizedToTest: true`. Browser flow handles BotID. | Deployment/source identity, fixture hash, job/Workflow IDs, authenticated owner; no customer secrets in repository artifacts. |
| Poll owner `GET /api/jobs/<jobId>` and `GET /api/jobs/<jobId>/progress`; answer `/messages` if qualification requests clarification. | Qualification decision/quote, current quote version, persisted commercial task/session and stage identity; pricing computed by code. |
| Owner `POST /api/jobs/<jobId>/accept-quote` with `{"quoteVersion":<current-version>}`; complete returned Stripe **test** Checkout; receive `/api/stripe/webhook`. | Matching accepted quote/payment/Workflow event, entitlement and one authorized execution. Do not use dev payment simulation on hosted production. |
| Observe audit, report and delivery; owner `GET /api/jobs/<jobId>/artifacts/report`. Repeat as another authenticated customer. | Investigator confirms only exact supplied evidence; report preserves labels/IDs and invents no findings. Commercial/investigator/operator `agent_persistence.tasks` retain completed session IDs; matching keyed `costs.source='naive'` receipts and provider measured amounts reconcile with stage/job reservations. Report is readable by owner and denied to unrelated customer. Retain report/artifact identity, terminal state, settlement/notification outcomes and total spend. |

The actual Workflow calls `recoverableEvalStage` for qualify/audit/report, which selects the real service directly in real mode. Verify these three calls have real session evidence and no mock/lite substitution. **The entire trace job is not guaranteed Naïve-only:** `finishReport` also attempts `proposeFixStep` for eligible findings; unselected `proposeAndVerifyFix` goes through the legacy real-to-lite fallback. Record that attempt, Gateway cost and any `fix_failed` event. Do not claim a verified fix or whole-job no-lite execution. A delivered confirmed-finding fixture must demonstrate how this ancillary step actually behaves; source inspection alone cannot certify it. Do not suppress genuine findings to evade this check.

Pass only with all required evidence above and no unresolved monetary obligations presented as settled. Failure/hold is a truthful outcome, not a demo pass. Roll back routing to `EVAL_SERVICES=lite` and redeploy the reviewed compatible source if needed; retain incurred costs, uncertain holds and immutable evidence.

## Existing drivers and missing automation

- `npx tsx --env-file=<private-staging-env> scripts/naive-smoke.ts --budget-usd 1` is a runnable **paid direct-core** qualify/report persistence smoke, not a hosted audit/payment/Workflow driver. It creates a fresh fixture each time, omits `auditTrace`, accepts budgets only in `(0, 2]`, and cannot prove replay or an aggregate authorization ceiling.
- `npx tsx scripts/e2e-pipeline.ts --base http://localhost:3100` is the existing local mock/dev pipeline driver. It requires `AUTH_DEV_LINKS=1`, `DEV_SIMULATE_PAYMENTS=1` and a development server; it cannot certify hosted real execution.
- No existing CLI automates this authenticated hosted three-role trace gate with real Checkout, session/cost/stage reconciliation and ancillary-fallback observation. Execute the browser/API checklist with private receipts or implement a separately reviewed driver; there is no invented hosted/trace/no-lite flag.
- Keep `npx tsc -p apps/web --noEmit` and `npm test` as source checks. Full strict conformance, full roster, native contention/restart/cancellation stress and full text/fail-fix acceptance remain separate rollout work; their absence does not itself refute this bounded demonstration, and this demonstration does not clear them.
