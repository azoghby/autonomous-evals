# Canonical expert text runtime consumer (owner review artifact)

Apply after the exact expert-workflow and rich-contract artifacts listed in `manifest.json`. Actual application/core source remains unchanged. `python3 docs/naive-text-runtime-integration/build-artifact.py` regenerates exact proposed postimages, preimage hashes, and `owner.patch` at the committed base. Expert Workflow postimages deliberately use the earlier artifact as their preimage; other paths use the base commit. No migration, provider call, activation, commit, or deployment is performed by this artifact.

The paid job Workflow consumes its existing SQL-provisioned expert plan once acquisition is ready. The consumer rechecks the immutable task/input identity, authenticated human review request/receipt records and operator principal, exact reviewed corpus, completed freeze operation and digest, frozen reference/provenance, canonical target prompt, owner/environment, deadline and enabled state. Mutable `last_result.status='ready'` cannot grant execution by itself. The immutable `expert_workflow.text_bindings` row binds the approved suite/customer/environment, target configuration and credential fingerprint, and run identity across restarts. A changed target or credential requires explicit owner reconciliation/new job; it cannot silently replay as the original target.

`createExpertTextRuntime` composes the existing rich run and investigation services with SQL checkpoints/admission/artifact stores, the existing durable Naive session runner, secured target transport and real Jude proxy service judge. Model, reservation and output limits must be explicitly configured; there is no default judge, mock/lite runtime, in-memory owner store, second evaluator, or new billing flow. Provider tests may replace transports; owner state remains SQL. Current authority and secrets are read again before each transport and publication. Measured session receipts are durably retained before a post-call publication check, replayed through the adopted keyed cost sink, and drained independently of target publication permission. Provider ambiguous effects remain fenced.

Rich execution is retained before projection. Public results preserve objective, rubric, inconclusive and infrastructure assessment kinds and exact check statuses/reasons/quotes. Only complete objective assessments expose a pass/fail boolean. Investigation consumes the retained canonical run and stores complete reproductions, findings, costs and limitations before public findings. Reports use the existing Naive operator service directly and existing private artifact/findings persistence, then existing job delivery/payment/notification flow. Assessment coverage, every scenario/check status/reason and investigator limitations are appended to the report. Zero assessable scenarios hold the Workflow and never proceed to delivery or settlement. Rubric concerns remain non-confirmed findings. No expert text route invokes lite fallback.

A ready suite now enters real run/investigation; `ready_consumer_required` is removed in these followon postimages. Pending sessions/reconciliation keep the existing bounded durable Workflow polling and prompt cancellation. Pending configuration, revoked grants, deadline expiry and ambiguous operations are explicit holds, never synthetic evaluation success.

This is **text baseline execution and investigation only**. Remediation/rerun verification is explicitly absent from its reports. General design, workflow evaluation, version comparison and full Phase 1 method routing remain separate work. Sandbox behavior is unchanged.

Owner prerequisites include the hardened automated-expert/atomic cost-sink adoption, current agent/data/checkpoint SQL, expert Workflow 0025 and explicit owner registration/application of proposed 0026. The proxy SDK has no provider-side monetary ceiling; its existing durable local reservations and measured audit reconciliation are used as provided by core. No production or real-provider completion is asserted.

Accounting limitation: core Jude now retains a minimal request receipt and can reconcile costs without returning a verdict after in-call authority revocation. A crash followed by plan revocation can still prevent this runtime factory from exposing the judge's replay path. Independent runtime reconciliation of those proxy requests is not installed by this text consumer; retain/reconcile the existing request and reservation rather than redispatching. The session receipt outbox described above does drain before target authority checks. This limitation must remain visible in adoption review.
