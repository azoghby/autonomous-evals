## Interfaces for the integration/media-lifecycle owner

`retainRuntimeRun({run, binding, issuePolicy, capture})` asynchronously returns `{run, seal, gateSnapshot, finalSnapshot, forget}`. Call it immediately after allocating the actual A run and before executing any tool. If construction rejects (for example stale policy), the allocating owner must dispose its raw run. Keep the raw run and database private: every subsequent call must use the returned wrapper. This is a trusted server adapter, never a constructor for customer/model/tool-provided authority.

- `binding` carries the original `worldId`, exact execution identity digest, admitted environment/scenario and all EvalVersions. The environment hash is checked using the same canonical JSON digest as executionDigest. The scenario hash covers the entire normalized scenario. Suite/runtime versions and run ID are preserved verbatim. No candidate/full-suite rebinding or run relabeling occurs.
- `issuePolicy(PolicyRequest)` returns `ExactRowPolicy | null`. The request includes run/world/execution, full scenario hash, env/suite hashes and every version. The response must repeat that exact request plus a nonempty server policy ID and exact allowed `RowMutation[]`. Policy is issued and detached before tools execute. The issuer receives no final rows or diff. It must resolve reviewed, admitted policy independently, with owner authorization and durable issuance upstream. A correct hash is a consistency check, not authentication of an untrusted issuer. Missing policy stays absent; writes then grade unknown. Malformed mutation grants remain unknown through the real grader.
- `capture()` receives no sampled evidence. It must retain the entire SQL database belonging to this actual raw run as an independent immutable image. It is called after the wrapper has drained accepted operations and `raw.diff()` has refreshed A's actual `sandbox_diff`, with trajectory and outbox detached, before disposal. `capturePGliteImage(owningDatabase, maxRows?)` is the supplied concrete **local** implementation. It exports and hashes the entire PostgreSQL data directory, then opens independent PGlite SQL databases from the private immutable Blob. No DDL or rows are reconstructed from summaries. A hosted backend must implement `RetainedSqlImage` with equivalent provenance and isolation; a live Neon connection is not a PGlite image source.
- `run` retains the original run ID, SQL/tools, diff, outbox and trajectory. Accepted operations serialize; tool arguments and query parameters detach at entry. `seal()` rejects new operations immediately and drains all earlier accepted operations before capture. It permanently seals the run, including on capture failure. `run.dispose()` memoizes seal then actual A disposal, attempting raw disposal even if capture fails. Failure cannot publish a partial snapshot or retry capture under the same handle. The owner still needs its normal bounded execution and cleanup deadlines.
- `finalSnapshot(artifact)` structurally implements the existing engine authority method for this run. It checks original run/world/execution, full environment/scenario, every version, complete diff **including A's actual summary samples**, trajectory and outbox against captured receipts. It never edits/relabels the artifact. The allocating owner retains a private run-ID registry and routes authority lookups to that exact handle; no fallback empty world or sampled reconstruction is permitted.
- `gateSnapshot()` seals and returns a snapshot for that exact reference/control/mutation run. Each run needs its own policy and snapshot. The gate composition owner must grade using the returned **snapshot.run**, rather than substitute evidence on a still-mutable raw run. Feed `snapshot.evidence` and additional independently bound media/security/refusal evidence into the existing gradeSandbox/bridgeGateGrade; do not overwrite the snapshot's row authority fields. The existing aggregate `collateral` check ID is unchanged.
- Each snapshot is `{run: GradingRun, evidence, release()}` and is structurally compatible with existing FinalSnapshot. It supplies `completeDiff`, `rowDiff` and optional `rowAuthority`, sharing one content-derived snapshot ID. Before issuing completeness it reads the actual fixed `ROW_DIFF_SQL` on the restored database and reconciles every table/operation count with the captured summary. The grader independently validates row images/keys and exact grants. No authorization SQL or parameter interpolation is used. A's five-row samples never establish row permission.
- `release()` closes only that independent read lease, with repeated release safe. Reads reject after release. Additional opens recover the same retained image and snapshot ID. `forget()` requires actual disposal and no active/opening leases, then drops the local retained image; later opens reject. The integration owner controls retention and invokes forget after report delivery/retention policy permits it. These process-local handles are not a durable snapshot repository.

The local snapshot query adapter uses A's exact SELECT/WITH validator plus PostgreSQL `BEGIN READ ONLY`, 5-second statement timeout and rollback, with bound positional values copied before queueing. Writes/CTE writes/stacked SQL reject. Returned rows are detached. The default 5000-row limit rejects oversized output rather than slicing and issuing a false complete receipt. A complete relation exceeding that bound remains unavailable/unknown; pagination or an independently reviewed bounded full-relation strategy remains an owner extension. The limit bounds delivered rows; the database still materializes the query result, so hosted memory/resource isolation needs separate enforcement.

Temporary staging is deleted on completion. This is actual local SQL/runtime acceptance, not a fake row relation or hosted runtime test.

The pre-existing `docs/track-b-runtime-parameter-fix/parameters.patch` is applied **only in temporary staging**, after clean applicability checking. It is required by the live wrapped run's positional-parameter acceptance check: unpatched A discards parameters. **Track A must adopt that patch (or its equivalent), validate against its current head and rerun its runtime tests.** B never edits A's actual sources. The retained image query implementation independently forwards bound parameters. No executed flags are invented; A's absent executed flag is preserved.

Coverage includes approved actual update pass; wrong row/value and unauthorized deletion fail; absent authority unknown despite true state SQL; stale policy rejection; immutable policy and identity checks; accepted-operation drain and late-write rejection; capture failure cleanup; SQL reads after actual live database closure; read-only/stacked/CTE protection; parameter detachment and timeout; uncapped fixed relation coverage beyond five sampled rows; over-bound refusal; same-image reopen/release; and explicit local retention cleanup. Additional approved insertion/deletion and nonpublic coverage are in the companion acceptance file. Final combined result: strict TypeScript, **18 tests passed across 2 files, zero failed/skipped**. Independent read-only review identified opening-lease cleanup and shallow tool-record ownership issues; both are fixed with regression tests.

## Remaining hosted gates

This bridge resolves the local immutable SQL/lifecycle and complete exact-row permission seam. It does not wire application routes or replace the separate integration/media team's files. Hosted acceptance still needs:

1. A-owned pre-disposal database copy/export and independent read-only retained database, with atomic durable publication, owner-only run registry, conflict-resistant storage, process-restart recovery, authorization, TTL/reaper, cancellation and crash cleanup. A finally block and this local in-memory Blob registry cannot supply those guarantees.
2. Production trusted policy issuance from exact approved suite/scenario and reviewed expected rows, separately for candidate gates and admitted execution; no deriving permission from actual writes. SQL isolation, full relation provenance including synthetic keys, and reviewed handling above 5000 rows remain platform gates.
3. Existing integration/media owner composition of wrapped allocations, authority lookups, gate snapshot grading, private report storage and independently attested media/security/exposure/outbox evidence. The SQL image retains outbox; it does not infer which external effects were safe.
4. A parameter-fix adoption, explicit executed-flag production evidence, secured provider/media transport, durable shared budgets and authoritative settled cost/attribution. This bridge does not convert unknown money to zero or make an overall statistical success eligible.

No secrets, cloud/provider calls, migrations, deployments, purchases, outreach or pushes occur in this work.
