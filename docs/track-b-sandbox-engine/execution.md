# Tool-loop execution handoff

Implements the execution leaf of `docs/SANDBOX_EVALS_PLAN.md` and the unchanged `sandbox-spec-v1` contract at `aa94505`. Source exports live in `packages/core/src/evals/sandbox/execution/index.ts`. No sibling implementation imports, runtime SQL/provisioning implementation, manifests, historical artifacts, or Track A paths are changed.

## Integration ports

- `executeToolLoopTrial(TrialInput, ExecutionPorts, AbortSignal?)` runs one isolated trial. Pass canonical admitted inputs, immutable version identifiers, explicit variant and seed, model/config digests and execution bounds. Parent admission is responsible for approval/oracle authority. `oracleValidated` alone grants nothing here. Parent `freezeSandboxInputs` / `verifySandboxInputs` from its identity implementation should supply verified inputs at eventual integration; this leaf does not import or duplicate that module. `executionDigest` hashes operation identities and checks the environment pin, not approval evidence or a full suite.
- `ExecutionPorts.runtime` is the exact Track A `SandboxRuntime`. Each trial prepares a uniquely named job-level world and starts a fresh `SandboxRun` with the original environment/scenario (including fixtures and scheduled faults). This intentionally favors isolation over pooling. Runtime owns named SQL binding, input-schema validation, database isolation, fault application, query safety and infrastructure recovery.
- `ExecutionPorts.checkpoints` uses existing `TextCheckpointStore`, production `PostgresTextCheckpointStore`. A non-expiring whole-trial intent precedes provisioning and all dispatches. Completed artifacts replay; pending/ambiguous trials refuse redispatch. Changing the same trial ID's inputs conflicts. Claims are never released. Parent must supply durable SQL storage, not a process-local map. Existing persistence migrations remain external dependencies, not runtime provisioning work in this leaf.
- `authorizeTrial({jobId, trialId, identityDigest, budgetMicroUsd})` is mandatory trusted server budget admission. It must establish an immutable cap under shared job/global/trial scopes; every paid target/simulator/media operation must reserve conservatively against those SAME scopes. It must retain ambiguous holds. This callback is not a free-spend switch: the secured adapters additionally require durable dispatch accounting. No prices are invented or token counts converted into dollars.
- `target({input,runId})` supplies a secured `ToolLoopTarget`. `createToolLoopTarget` reuses the existing DNS-pinned, public HTTPS/TLS transport, byte/time/concurrency bounds, credential checks, and structurally compatible `PostgresRemediationAccounting` hooks. Bind instance methods. Configure reservations with shared global/job/trial scopes and worst-case dispatch amounts; settling money requires authoritative reconciliation receipts. It pins endpoint/model, temperature, seed, completion cap, tool schemas and transport bounds in `configDigest`. Include environment `systemPrompt` through runner messages. Explicit test-only compatibility evidence uses `baselineRunId=runId` and `patchDigest=configDigest`; these are not actual remediation evidence or remote attestation. A production accounting vocabulary specific to sandbox trials remains parent integration work.
- `SimulatorPort` accepts only projected user/assistant conversation. `createConstrainedSimulator` exposes only upfront facts plus explicitly authorized when-asked indices to its driver; never facts are excluded. No tool results, arguments or trajectory are sent. `authorizeFacts` must be trusted explicit question/fact authorization; absent it, when-asked facts remain unavailable. Arbitrary NLP classifiers cannot prove fact safety.
- `createGatewaySimulator` uses the secured HTTPS transport, bounded JSON-schema output, pinned model/config and per-trial seed. Mandatory `beforeDispatch` must atomically reserve and fence the exact operation/payload across restarts; `observed` preserves actual token evidence and `ambiguous` holds unknown outcomes. Wire this to durable accounting, not no-op callbacks. No ambient credential is read. A token function is required. No SDK/provider call was made for validation.
- `TrialMediaPort`, `VoiceTurnPort` and `prepareTrialMedia` provide useful typed generation/rendering, TTS/STT, perception and private-asset receipts. Oracle inputs omit expected facts and verify pinned model/config, asset digest, byte limits and independently observed ground truth. Media-generation/perception ports must fence/account externally; caller must finally call `dispose(trialId)` including on partial preparation. This helper alone has no deadline; implementations/callers must bound it. Video rejects explicitly.

## Execution behavior and artifacts

Assistant tool batches execute sequentially in their single trial world. Tool-level returned errors/faults become tool responses and remain in artifacts. Unknown tools, duplicate call IDs, step/turn/tool/message bounds, aborts, deadlines and port exceptions stop execution. Runtime tool-schema validation is mandatory; this runner never executes SQL itself. Target requests include `parallel_tool_calls:false` and the adapter still accepts a bounded batch, executing it in order.

`TrialArtifact` separates execution status, reason, ungraded conversation, tool records, diff, outbox, input/version/seed identity, elapsed time, world/run handles, cleanup evidence, infrastructure uncertainty and monetary uncertainty. `completed` means the simulated user chose a terminal disposition; it does not mean task success. `bounded` means a bound stopped the trial. There is deliberately no legacy `passed` projection. Parent grading must use evidence and must not convert missing evidence, unknown cost, a simulator's `goal_achieved`, or cleanup uncertainty to a pass. Cost is always `{status:'unknown',microUsd:null}` until parent joins authoritative accounting receipts, including infrastructure receipts. Tool traces remain separate from simulator conversation.

Every acquired run/world gets a bounded cleanup attempt in `finally`; late provisioning completions also trigger cleanup attempts. Failure to confirm disposal remains unknown. Track A's contract has no abortable/idempotent provision handle or tool cancellation: if allocation creates resources and rejects without returning a handle, this leaf cannot address them. If a worker dies, cleanup cannot run locally. The durable root fence prevents duplicate execution, but parent must reconcile pending trials and ask Track A to implement TTL/reaper recovery. An in-flight timed-out tool or HTTPS call may finish after abort or disposal; a cleanup attempt is not proof of remote cancellation. No automatic retry, resume of partial worlds, or restart dispatch is performed.

## Supported scope and limits

Text `tool_loop` works with real supplied runtime and secured target ports. `sandbox_api`, `repo`, `staging`, `realtime_voice`, voice/multimodal personas and any attachments are explicitly unsupported by this runner before provisioning. The media helper is separately callable; binary target delivery, realtime turn-taking and provider implementations are not fabricated. The constrained simulator chooses fixed utterances and permitted fact indices rather than arbitrary prose: place the actionable initial request in upfront knowledge. This limits naturalness/trait fidelity. Goal/style/conversation can contain overlapping facts; no claim of arbitrary-language semantic secrecy is made. The simulator's stop decision is diagnostic and requires parent grading.

Parent must bind current authorization/secrets, suite admission, target factory endpoint/config/seed, runtime identity and budget scopes on every invocation, including artifact replay. This leaf pins supplied identifiers; it cannot attest remote model execution or authorize customer endpoints. Stored artifacts contain scenario knowledge and private tool output: use owner-only storage/retention/redaction before reports. Injected test transports are trusted server-only fixtures and must never come from customer input.

## Offline validation

From the repository root, with existing dependencies (no install needed):

```sh
node tests/track-b/sandbox-execution/check.mjs /absolute/path/to/node_modules
```

The dependency directory needs TypeScript, Vitest, zod, ipaddr.js and Node typings from the existing Track B harness. The check stages existing source in a temporary directory, writes the **exact unmodified** `git show aa94505:packages/core/src/sandbox/spec.ts`, stages existing core contracts from the same ref, runs strict TypeScript and focused tests, and removes staging. It never edits Track A or substitutes an altered shadow contract. Parent's updated shared harness can stage this same spec for broader integration.

Tests exercise runtime fakes with distinct mutable worlds, sequential writes and tool fault records; completed replay, pending crash fences, changed-identity rejection, lost completion acknowledgements; explicit disclosure, unknown-money retention, abort/deadline and late allocation cleanup; cleanup/simulator errors; pinned target requests, accounting order, budget denial, malformed output, late usage; structured Gateway simulator dispatch and media-oracle mismatch/video refusal. These are offline implementation checks, not SQL isolation proof or live Neon/Gateway acceptance. No secrets, provider/cloud calls, deployment, spending or paid-cost evidence were used.
