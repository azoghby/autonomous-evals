# Sandbox engine integration

Owned additions: `packages/core/src/evals/sandbox/integration/`, `tests/track-b/sandbox-integration/`, and this document. Baseline plan and shared spec were read with `git show aa94505:docs/SANDBOX_EVALS_PLAN.md` and `git show aa94505:packages/core/src/sandbox/spec.ts`. Exact commit: `aa94505fd535f5c0f586cc6325b49b71a1683761`. No shared schema, original leaf, platform, app, manifests or historical release evidence is changed.

`createSandboxEngine(config)` composes existing Engineer generation, actual oracle/null/mutation gates, frozen input identity, exact customer admission, tool-loop execution, deterministic grading and repeat statistics. There are no default runtimes, credentials, provider clients or storage. All ports are trusted server dependencies and must never originate in customer/model/tool JSON.

- `generate(request)` binds existing durable Engineer operations and cost delivery through `createSandboxGenerationAdapter`. Every candidate calls actual `runScenarioGates`; successful completed generation returns an unapproved artifact using those same passing receipts, without executing the gates a second time. Dropped slots remain visible. Pending or blocked work cannot become approved.
- `propose({environment,scenarios,operationKey})` freezes and verifies supplied scenarios and runs the same gates; it supports reviewed or edited suites. It refuses incomplete gates. A new operation key is a new authorized gate operation, not a retry key.
- `run({artifact,versions,trial})` reauthorizes the current caller and resolves immutable server-held approval on every invocation, including replay. It binds exact scope, suite/evidence digests and approval ID, freezes the admitted inputs, checks environment/suite/runtime/judge pins, and dispatches the existing fenced trial runner. Seed, model/config, simulator config, bounds and variant remain in execution identity. The job identity always comes from the factory scope.
- The whole composed trial has an additional durable `replay.once` fence; lost report-delivery acknowledgements redeliver the identical private report rather than redispatch. A pending or ambiguous operation requires reconciliation, never a fresh attempt under the same key. Execution also retains its own durable checkpoint fence.
- `summarize(reports,k)` uses rich outcomes and the existing deterministic reliability/Wilson implementation. Missing, unknown and unattributed outcomes remain explicit exclusions. It must consume reports loaded from authorized private storage, not customer-supplied outcome objects.

The gate bridge calls the real `gradeSandbox` implementation. It aggregates grader `security:*` predicates and canary evidence into admission's `security`, and ground-truth field checks into each `media:<attachment>`. Missing evidence, empty ground truth, duplicate IDs and reward-bearing unknowns make `complete:false`; unknown is never a resolved negative control or mutation. Diagnostic checks remain diagnostic. Mutation coverage targets the aggregate admission check, and the rich report retains individual grading evidence. These receipts prove only what the trusted runtime/predicate ports actually tested.

## Final-state authority and private reporting

The execution leaf disposes its run and world before returning. Therefore `authority.finalSnapshot(execution)` must load an immutable quiescent final SQL snapshot retained **before disposal**, identified by the exact execution run ID. It supplies SELECT-only, timeout-bounded grading queries, complete diff and trajectory evidence, approved refusal phrases, security predicates/exposure, perception mappings and any calibrated rubric evidence. The factory compares its actual diff and trajectory with the execution artifact, grades against admitted rules and transcript, and releases the snapshot. A missing, mismatched or uncleanly released snapshot remains unresolved. Sampled rows and transcripts cannot reconstruct the final database or prove complete row coverage.

`persistPrivateReport` must implement an owner-only durable upsert keyed by execution identity, reject conflicting replacement, apply authorization/redaction/retention and retain the original artifact plus rich checks. Returned reports are detached. They are **private report inputs**, not public route/report DTOs. Runtime allocation, retained snapshot capture, report retention and crash cleanup require platform implementation; TypeScript ports do not attest a dishonest adapter.

Execution currently returns money as `{status:'unknown',microUsd:null}` even for completed trials. The integration preserves that exactly. A deterministic read-only/refusal grade may pass while the overall statistical outcome remains unknown because costs are unsettled. No numeric `TrialResult` or settled money is invented; current integrated reliability explicitly excludes these outcomes. Track A must supply authoritative, replayable settlement receipts covering target, simulator, infrastructure and media, bound to execution identity and shared budgets, before an overall eligible success can be projected. This conservative limitation is intentional and must stay visible in reports.

## Precise platform contract prerequisites for Track A

The intended end state remains a stateful sandbox: customer tools bound to real isolated SQL, frozen-clock fixture worlds, actual reference agent gates, repeated secured tool-loop trials, then state/trajectory/output/collateral/security/perception grading and private reports. This implementation does not reduce that goal to text matching or leaf mocks.

1. **Row-level write authority:** v1 `allowedChanges` contains only `{table,description}` despite promising predicates. Required amendment: exact approved row predicates or a complete before/after diff relation exposing stable row identities, operation, old/new values, plus immutable policy/suite/run binding and completeness attestation. Mutations must demonstrate both authorized writes and same-table unauthorized writes. Allowed table membership and `StateDiff.sample` are insufficient. Existing grader unknowns for writes inside an allowed table remain unchanged. No supplemental proof silently overrides those grades.
2. **Snapshot lifecycle:** atomically publish an immutable final snapshot/trajectory/diff/outbox receipt before teardown; support read-only snapshot queries, resource TTL/reaper, disposal receipts and crash reconciliation. A worker crash cannot rely on local `finally`. Supply keyed provisioning/tool cancellation and ambiguous-operation recovery.
3. **Durability and authorization:** real SQL-backed gate replay, operation binding, existing AgentSession task/budget services and TextCheckpointStore; atomic approval ownership and replacement rules; caller reauthorization on every replay; immutable snapshot/report upserts and privacy controls. In-memory implementations are test fixtures only.
4. **Money and reporting:** authoritative settlement schema including unknown/pending, infrastructure cost and latency/budget telemetry; reviewed failure attribution; private storage/report projection and progress/queue integration. Do not count simulator/environment/grader/unknown failures as customer failures.
5. **Execution coverage:** production isolated SQL/fixture validation, tool input-schema checks, read-only grader enforcement and statement deadlines; secure target and simulator reservations under the same durable cap; explicit security predicates covering action and unauthorized-state/outbox effects. Local SQL acceptance is not Neon or microVM isolation acceptance.
6. **Media/modes:** actual rendered/generated assets with independent oracle receipts, exposure and tool-argument perception bindings, private asset lifecycle, voice latency/turn-taking, binary target delivery, realtime/repo/staging/sandbox_api adapters. The current tool-loop leaf rejects nontext and attachments; aggregate bridge support does not enable those transports. Video remains deferred.
7. **Broader product acceptance:** calendar/environment bridge, approved-suite remediation and CI/monitoring/report consumers, fidelity calibration, paired simulator spread and human attribution review. Existing release/autonomy work is independent. No cloud/provider acceptance, secrets, paid spend, deployment or push is claimed here.

Security control eligibility is also unresolved for attacks delivered only through tool calls: do-nothing/empty controls never encounter that tool result. The grader correctly marks absent exposure unknown, so admission cannot treat such a control as a resolved security failure. Platform needs an explicitly approved exposure/control-eligibility protocol or a world that delivers the attack before control behavior. Never fabricate exposure to obtain green admission. Candidate gate rubric versions use the exact one-candidate frozen suite identity; full-suite calibration must be separately collected/bound after suite assembly.
