This migration is additive to the **f88811c** owner artifact and its **0398517** current app base. It does not modify application tables or replace the billing contract. Apply it through the owner's migration runner after the exact app baseline and `company_autonomy_release` schema, inside the runner's transaction. Reapplication preserves retained events/bindings/outbox.

The binding stores SHA-256 quote/request digests supplied by the reviewed canonical TypeScript adapter; SQL independently checks current application job/quote/payment identity. SQL is not a provider signature verifier. Only the reviewed server role may call `ingest_event` after signature verification. Functions use invoker privileges; PUBLIC has neither schema/table/function authority. Role provisioning remains an explicit owner configuration gate.

`prepare_binding(tenant,job,version,quoteDigest,requestDigest,environment,amountCents,sessionId)` supports a null session while the actual checkout path prepares it; the first canonical session is then immutable. Quote/request identity conflicts raise and roll back. `ingest_event(tenant,job,version,provider,environment,eventId,eventDigest,sessionId,amountCents,currency,status,quoteDigest,paymentId)` retains verified events and durable outbox work atomically. `paid`, `refunded`, and `cancelled` are supported. Refund/cancel revokes the entire fixed-payment authority conservatively without initiating a refund. Partial refunds never leave residual spend authority.

`publish_receipt(tenant,job,eventId)` drains after bootstrap has created the release binding. A pre-bootstrap payment stays durable in the outbox. Invalid/currently revoked authorization returns `waiting_or_revoked`; nothing is silently delivered. `receipt_valid(tenant,job,quoteDigest,receiptId)` rechecks current owner, release enablement, job environment/mock/terminal state, latest fixed accepted quote/session, exact payment currency/amount/status, and absence of a competing payment. A later stale/cancelled event can never restore revoked authority. Provider receipt ID is `stripe:<environment>:<eventId>`.

The outbox query is an ordinary join of `events` and `outbox` on `(provider,environment,event_id)`, filtered by exact tenant/job and `NOT delivered`. Acknowledgement follows successful receipt publication. Repeating publication is safe; no Workflow start or provider action occurs in these functions. The owner still must schedule a trusted drain; the startup artifact supplies its registration seam.

Native tests run PostgreSQL with the existing offline PGlite dependency and execute the retained actual app baseline migrations (0000 and 0006), then the release schema and this migration. They do not call Stripe, x402, cloud, or a network service. Run `node --test tests/track-b/current-autonomy-payment-startup/sql.test.mjs`; set `AUTONOMY_NODE_MODULES` to an existing directory containing `@electric-sql/pglite` if necessary.
