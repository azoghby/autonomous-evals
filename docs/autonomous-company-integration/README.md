# Policy-bound unattended company integration

This additive implementation activates only explicit server-owned versioned autonomous authority. Existing human data review, Commercial draft outreach, and manual Workflow paths are unchanged. No ECC, provider calls, sending, secret reads, cloud changes, migrations against hosted storage, deployment, push or PR were performed.

## Executable evidence

Run `node tests/track-b/autonomous-company/verify.mjs`. It stages current core and the owned tests, applies/checks `application.patch` against an empty application path, compares the result to source, strictly checks transitive TypeScript and executes real PostgreSQL SQL with PGlite. It uses already installed offline dependencies (`AUTONOMY_NODE_MODULES` overrides the machine-local default). No install or external endpoint is involved.

The combined acceptance executes intake-ready → Commercial qualification → code-owned fixed quote → authoritative scripted payment wait → automated evidence admission → Engineer twelve-scenario design → independent Investigator review → freeze → actual Text execution against a fake target → evidence/limitations → Operator summary → actual Markdown/HTML/JSON rendering → durable report publication → bounded outbox. Restart reuses SQL tasks, run, artifacts and notifications. Fake transport delivery is separately exercised. Founder interventions are zero. All four Naïve roles use actual SQL task and budget services with pinned version 1, scripted provider responses only. This proves operating code against controlled fixtures, not autonomous production acceptance or useful unrestricted factual judging.

## Apply and compose

1. Install existing agent `001-agent-persistence.sql` and data `002-data-operations.sql` in the owner's established order. Apply `packages/core/src/agents/autonomy/operations.sql` and exported `AUTONOMY_COMMUNICATIONS_SQL` with unique migration identities and server-only grants. No model/customer SQL access.
2. Import the new modules by explicit subpath; no existing exports/contracts/manifests need editing. Apply `application.patch` to the assembled owner app (`git apply --check` first). This adds a server composition adapter only and does not replace final-composition, judging, comparison, rerun or review-resumption files.
3. Construct immutable `createAutonomousPolicy` from authenticated setup. Retain defaults $3 single/$5 comparison and $35/$65/$65/$35 period caps unless explicitly configured within the existing root. Configure exact provider agent IDs/versions. Agents and customer payloads must never write policy, clocks, receipts or budgets.
4. Construct `AgentSessionService` with the existing SQL task store, `createAutonomousBudgetLedger(new PostgresBudgetLedger(db), policy)`, and directory generated from `policy.agents` (`agentId=id, agentVersion=version`). Wrap it in `createAutonomousRunner`. This adds root and configured lower role authority to the **same atomic reservation**; do not charge supervisor envelopes again as measured cost. `createAutonomousRunner` enforces configured job ceiling and current policy/secrets. Reuse period identities across restarts.
5. Supply current authorization on every job/target/data/outbox call. `createAutonomousDataAdmission` consumes source hashes, independent producer identity, authenticated retrieval/permission receipts and exact supported facts from trusted server configuration. It does not make a model a licensing authority. `acquireAutonomousData` executes bounded discovery/generation callbacks, persists immutable results, and sends only an outbox proposal to an approved consented expert. Paid discovery/generation adapters must retain their own existing atomic reservations/receipts. Pending effects cannot be retried by this helper.
6. `createAutonomousTextEvaluation` bridges this separate automated authority into the actual Text design/review/execution/investigation services. It never writes a forged authenticated-human review. Use guarded, durable target/judge adapters; `judge:null` remains explicitly unassessed. `CompanyPorts.data` should call the acquisition helper and pass its final admitted snapshot to the Text adapter. `CompanyPorts.evaluate` and `recoverEvaluation` bind the same immutable key; lost acknowledgements read retained receipts, never create replacement runs.
7. Map `CompanyPorts.enqueue` to `PostgresCommunicationOutbox.enqueue` with a hash of the operation key and server-resolved customer contact. Its mandatory `authorizeContent` must check outstanding clarification, frozen quote, or a published report owned by the current job. Store clarification questions in authorized intake state before enqueue; the email template tells the customer to return there. Report-ready may be queued only after `:published-report` exists. Publish/map that retained artifact to the owner's authenticated report route before enabling delivery. The artifact includes rendered HTML/Markdown/JSON; no Blob claim is implied.
8. Configure sender, contact audience, product-notification permission, marketing opt-in, expert consent, opt-out, daily cap, delivery deadlines, current secret scanner and authoritative idempotent provider receipt lookup. The transport is dependency-injected and remains omitted in offline setup. Monitoring offers require marketing opt-in; actual subscription, retest and monitoring runs remain separately authorized owner services, not automatic charges.
9. Call `createAutonomousCompanyServer(...).scheduledTick()` from the owner's authenticated scheduler (for example once per minute). Supply bounded current due-job selection, current ports, supervisor receipts and optional transport. It ticks at most 25 jobs, runs bounded recovery, and returns a daily audit view. It never creates/restarts physical Workflow runs. Persist/surface its exception outcomes in the operator console. Do not replace existing resumption semantics or delete their pending claims.

## Safety and limits

Company decisions have immutable request binding, reason, policy version and known/unknown cost status. SQL supervisor action claims and messages retain ambiguity and bounded deadlines; authoritative absent/sent receipts govern recovery. Session unknown usage keeps reservations. Source/model text cannot grant authority. Unknown payment waits for the actual webhook/reconciliation source. Billing/refunds remain policy-bound proposals and existing manual financial exception handling; no transfer adapter is added.

The app adapter is an applyable, strictly checked composition seam. Owner startup wiring, actual authenticated report publication, cron registration and provider configuration are explicit setup gates; this artifact does not silently activate itself in owner code. Existing session service legacy ambiguity recovery must be configured not to replay paid creates when the provider lacks authoritative idempotency/receipt guarantees. Unavailable receipts or dead old-definition Workflow runs remain honest exceptions, not claims that the company completed the job.

PGlite runs PostgreSQL SQL on one embedded connection: concurrent Promise cases establish atomic serialization/idempotency behavior, not hosted multi-connection lock contention. Hosted PostgreSQL contention, Workflow build/replay, real inbox/reply correlation, live Stripe and actual target/judge/transport receipts remain owner acceptance gates.
