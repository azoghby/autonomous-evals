## Concrete authority and dispatch

Internal Workflow `createRichWorkflowServices(ctx,{workflowRunId,judgeRuntime?})` wires Text and remediation to one resolver; production comparison accepts its internal runtime as the second argument. No HTTP body chooses the judge model, key, budget policy, transport, or runtime. Production policy is server deployment configuration: `WORKFLOW_JUDGE_MODEL`, `WORKFLOW_JUDGE_CONFIG_VERSION`, `WORKFLOW_JUDGE_RESERVATION_MICRO_USD`, `WORKFLOW_JUDGE_AUTH=api_key|oidc`, and the shared `NAIVE_BUDGET_PERIOD_ID`. Credentials resolve freshly through the fixed private reference `AI_GATEWAY_API_KEY` or `VERCEL_OIDC_TOKEN`. These names are references, never values in artifacts. Missing configuration refuses; there is no unauthenticated fallback. Construction does not read credential values.

Production dispatch uses actual `createGatewayJudge`, its fixed Vercel HTTPS endpoint, Bearer API-key/OIDC authentication, 2048 completion cap, bounded response parser and 30-second per-call timeout. The enclosing runtime combines parent AbortSignal with that timeout. Its default runtime limits each service instance to 16 Gateway dispatches over 180 seconds; durable budgets/claims span instances. Acceptance must supply its actual durable `beforeDispatch` meter and parent signal through the internal runtime. An injected fetch exists solely for offline tests and does not establish live provider evidence. No arbitrary port or callback can claim live acceptance here.

Each call hashes original input + fixed model/config/private reference + current job/target identity. A persistent checkpoint and an existing accounting operation reserve both job and shared evaluation-engineer period scopes before dispatch. A permanent row-lock claim precedes the parent meter and HTTP call. Pending/ambiguous claims never expire or blindly retry across restarts. Same ID with changed input refuses. The job, credential revision and current secret guards are refreshed before credentials, dispatch and replay; private Gateway token content is guarded without persistence.

Gateway usage is authentic parsed token evidence, never a made-up dollar amount. Unknown price retains the hold/outbox even after successful rubric evaluation. Owner/provider reconciliation uses `JudgeAccounting.reconcile` → existing core ledger settlement and the shared globally keyed delivery transaction. A lost acknowledgement replays once with no duplicate money. It does not retry the model. Invalid citations or malformed/failed replies stay unresolved and retain usage/holds; reference-required checks remain unassessed. Rubric outcomes remain subjective and never become objective confirmations. Remediation's outer checkpoint wrapper returns no duplicate cost entries because the shared accounting delivery owns money.
