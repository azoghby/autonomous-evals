## Durable dispatch, abort and evidence

The local meter fsyncs an attempt before ACK, shares an exclusive filesystem lock
across workers, retains counts/deadline through restart, rejects duplicate IDs and
changed limits, and fails closed on torn logs, stale locks or persistence errors.
A lost ACK consumes capacity; retries do not reuse an acknowledged ID. Operators
must reconcile crashed locks, never delete them automatically. Use a private local
ledger directory. Hosted multi-machine durability needs owner transactional storage
with this same contract; local filesystem tests do not attest hosted PostgreSQL.

The internal runtime meters the actual Text/Calendar/remediation transport and
Naive create/get/list calls. Gateway admissions go through both production policy
and durable acceptance meter. Target transport receives the parent AbortSignal
inside its DNS/HTTPS path; SDK fetch and Gateway combine parent cancellation with
their own signal. Meter failure aborts subsequent dispatch. Underlying target
request timeout still applies. A port wrapper alone does not claim cancellation of
an arbitrary injected transport that ignores its signal.

Existing independent Calendar SQL grading, private tenant report reads, durable
unknown-cost operations and separate-process restart tests are rerun unchanged.
Their synthetic objective-only Text fixture remains labelled offline and does not
become rubric-bearing live acceptance. The actual judging suite separately retains
all original accepted base12 objectives/rubrics and authentic parsed fixture usage.
No null judge result or synthetic Naive response grants live acceptance.

replacement SHA256. No candidate proposal can set that variable or approve itself.
A real engineer proposal must be reviewed out of band, exact bytes frozen, and host
configured before trial admission. Preserve its original task/session/cost plus raw
