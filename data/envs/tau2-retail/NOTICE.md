## What was converted / adapted

- **Tools**: the 15 retail tools (same names and arguments as `tools.py`), expressed as an OpenAPI document with `x-sandbox-sql` bindings (`openapi.yaml`, generated by `scripts/tau2/gen-retail-openapi.ts`). Preconditions that `tools.py` enforces with `ValueError` are encoded in SQL; a failed precondition leaves the database unchanged and the call returns a `not_found` error.
- **Database**: `db.json` normalized into relational tables (`schema.sql`). `seed.sql` is a deterministic subset (32 users, their orders, the full 50-product catalogue) produced by `scripts/tau2/convert-retail.ts`.
- **Policy**: `policy.md` re-formatted into numbered clauses (`policies.md`); wording is kept.
- **Workflows**: `workflows.json` is new, written by Standard Evals.
- Tools return JSON objects where upstream returns bare strings (`find_user_id_*` -> `{user_id}`, `list_all_product_types` -> `{product_types}`).
- `calculate` has no SQL equivalent and uses a simulated (LLM) binding; `transfer_to_human_agents` records to `sandbox_outbox` and returns `Transfer successful`.
- `modify_pending_order_items` gives each replaced item its own new price/options (upstream reuses the last variant's price/options for every line when several items are modified in one call).
- The read-only `get_item_details` tool of upstream `tools.py` is not part of the 15-tool set and is omitted.

Converted by Standard Evals.

## Verbatim upstream policy

`upstream-policy.md` is an unmodified copy of upstream `data/tau2/domains/retail/policy.md`. It is used as the
`<policy>` in the tau2 reference agent's system prompt (`scripts/real-agents-sandbox.ts`), so that agent sees exactly
the policy text it was designed for.
